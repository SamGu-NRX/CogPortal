# Script, with slide changes

Hi, I'm Sam. **[SLIDE 1]** Cog\*Portal scores a CogWorks capstone by running
the student's own code, and I want to show you what that buys the course.

**[SLIDE 2]** This year there were thirteen repositories across the three
capstone weeks. Four of them could be scored automatically, and each of those
four only because an instructor sat down and hand-wrote the wiring for it. That
does not scale to a cohort, and it is not a thing you want a TA doing at
midnight.

**[SLIDE 3]** The reason it is hard is that there is no convention to lean on.
One team calls the function that stores a song `add`. Another calls it
`store_fingerprints`. A third keeps the database on an object and passes it
around. You could force everybody to use the same names, but the freedom to
build it their own way is most of what the capstone is.

**[SLIDE 4]** So the rule is: names propose, running decides. A name can order
the candidates. Only running the code is allowed to pick one, because a wrong
guess still returns a number, and a plausible wrong number is worse than saying
nothing. The platform enrols two songs through their functions and asks for one
back. Whatever answers correctly is what it scores.

**[SLIDE 5]** Every repository with a working pipeline now scores. This team's
functions are called `add` and `query_details`, and nobody wrote them an
adapter. When a repository does not work, it says where: the file, the line,
and what raised. Half a real cohort meets that message before they ever see a
score, so it has to be worth reading.

Then the demo: terminal, then the site.

## Build rules

- Five slides. Seven or eight visuals total across the whole deck.
- At most eight words visible per slide, excluding the two scores on slide 5.
- No bullet lists.
- The narration lives in the speaker notes, so the file he presents is the file
  he rehearses from.
- Export a PDF for presenting and keep the editable file for Google Slides.
