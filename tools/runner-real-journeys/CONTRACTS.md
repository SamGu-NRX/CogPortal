# Harness contracts

One page, so every sub-thread builds pieces that fit. Nothing here modifies
runner or Worker source; the harness lives only under `tools/runner-real-journeys/`.

## Process topology (one journey = one fresh stack)

| Piece | Port | Implemented by | Notes |
|---|---|---|---|
| Stack entry | — | `stack/bootstrap.sh` | One command for the stack: runs `setup-host.sh`, then starts edge + runner with suite-only env (`SSL_CERT_FILE`, `REQUESTS_CA_BUNDLE`, `NODE_EXTRA_CA_CERTS` for the local CA). Nothing system-wide: no `/etc/hosts` edits, no CA-store install; host git/gh keep the real GitHub. |
| Edge (HTTPS) | 443 | `stack/edge.py` | SNI router: `cogbox.local` → Vite dev server, `api.github.com` → corpus tarballs. One cert authority generated by `stack/setup-host.sh`, trusted by suite processes only; sandbox namespaces bind-mount the suite-private hosts file and suite processes resolve both names through the `stack/localresolve.py` getaddrinfo override. |
| Vite + Worker dev | 5175 | `pnpm dev` (repo's own) | `.dev.vars` written by the orchestrator: `EXECUTION_PROVIDER=modal`, `MODAL_RUNNER_URL=http://127.0.0.1:8791`, `RUNNER_SIGNING_SECRET=<suite secret>`, `RUNNER_SIGNING_KEY_ID=runner-v1`, `PUBLIC_ORIGIN=https://cogbox.local`, `DEV_AUTH=enabled`. |
| Runner (real controller) | 8791 | `stack/runnerbox.py serve` | Imports `apps/runner-modal/src/cogworks_runner/modal_app.py` verbatim through the shim (`stack/sandbox_shim.py`). Speaks the same signed protocol as the deployed `submit_job` endpoint. |
| Callback shaper | 8792 | `stack/callback-proxy.py` | Sits between runner and Worker for the `callbacks` lane; transparent forward by default, fault rules per run id. |
| Local D1/R2 | disk | wrangler/miniflare state | Wiped per journey: `rm -rf` the state dir, re-run migrations + `scripts/seed-local.sql`. |

## Runner thread model

- `runnerbox serve` handles `POST /` (any path) by calling the real
  `modal_app.submit_job` with a shim `Request` (`.body()`, `.headers`) and returning
  its shim `Response` status. Signature verification runs for real
  (`RUNNER_SIGNING_SECRET`, `RUNNER_SIGNING_KEY_ID`).
- `execute_job.spawn(job)` runs the real `execute_job` in a thread pool. The
  thread sets a thread-local with the job's track (from
  `cogbench.environment.track_for(job["benchmark"]["id"])`) so the sandbox shim
  picks the right interpreter stack.

## Local Sandbox semantics (shim, in `stack/sandbox_shim.py`)

- `Sandbox.create(image=..., app=..., cpu=(lo,hi), memory=(soft,hard), timeout=s,
  block_network=bool, outbound_domain_allowlist=[...])` → a private sandbox:
  `sudo unshare --mount --uts --pid --fork --mount-proc [--net] bash -c '...mounts...;
  exec "$@"'`. `/tmp` and `/workspace` are bind-mounted to the sandbox's private
  directories; a private cgroup2 mount enforces `memory.max = hard`, `memory.high =
  soft`, `pids.max = 512`, `cpu.max` from the cpu range; `--net` when
  `block_network` is true. Wall clock `timeout` kills the cgroup (`cgroup.kill`)
  and the exec reports returncode 137. An OOM (`memory.events` `oom_kill` grows)
  raises `RuntimeError("... out of memory (oom) ...")` after `wait()`, which the
  controller's `"memory" in str(error)` catch maps to `memory_limit`, matching
  Modal's exception-shaped OOM. A wall-clock kill does not raise; the controller's
  `_timed_out` (elapsed vs budget) classifies it.
- `filesystem.write_text/write_bytes/read_text` translate `/tmp` and `/workspace`
  into the sandbox's private dirs; the runner process does these directly.
- `snapshot_filesystem()` tars the private trees into `BOX/snapshots/<id>.tar.gz`
  and returns `.object_id`; `Sandbox.create(image=Image.from_id(<that id>))`
  extracts the tar into the new sandbox's private dirs. Course stacks are NOT in
  these trees — they live in `BOX` venvs outside the sandbox paths, so snapshots
  stay small and nothing student-writable is shared between sandboxes.
- Interpreter selection, per exec: argv[0] `/opt/cogworks-py38/bin/python`
  (`ENVIRONMENT.PY38_VENV`) is replaced by `BOX/<track>-py38/bin/python`
  (week1, week3); argv[0] `python` resolves through a PATH that puts
  `BOX/week2-py311/bin` first (week2). Other argv[0]s run as-is.

## Box layout

```
/home/user/work/cogbox/
  week1-py38/  week3-py38/  week2-py311/   # course stacks (build_envs.py, running)
  sandboxes/<id>/{tmp,ws,cg}/              # private sandbox trees
  snapshots/<object_id>.tar.gz             # filesystem snapshots
  corpus/                                  # tarballs + sha map (built from corpus/)
  logs/                                    # env build logs, stack logs
```

## Run path for a corpus case

1. Dev-auth login: `GET https://cogbox.local/api/dev/login` (see
   `apps/portal/worker/routes/dev-auth` for the exact shape; the orchestrator's
   `lib/portal-client.mjs` wraps it).
2. Create/join a team joined to the fixture repository (`cogworks-demo/face-finder`
   — `FixtureGitHubClient`, no real GitHub).
3. `POST /api/runs/practice` with `{teamId, benchmarkId, branch: <case name>}`.
   The branch name selects the case: `FixtureGitHubClient.resolveRef` derives the
   sha from the branch, the run records it, and the runner's prepare fetches
   `https://api.github.com/repos/cogworks-demo/face-finder/tarball/<sha>` —
   answered by the edge from the corpus map for that sha.
4. Poll `GET /api/runs/:id` (auth'd) until terminal, then assert the pass bar.

## Receipt format (written per journey to `receipts/journey-<N>.json`)

```json
{ "journey": 1, "startedAt": 0, "finishedAt": 0,
  "cases": [ { "id": "week1-import-error", "week": 1, "lane": "broken-code",
               "pass": true, "checks": [ { "name": "category", "pass": true,
               "expected": "dependency_install", "actual": "dependency_install" } ],
               "runId": "run_x", "url": "/runs/run_x" } ],
  "summary": { "passed": 0, "failed": 0 } }
```

`pass` is false unless EVERY check passed. A case that errors before starting is
recorded with `pass: false` and a `checks: [{name: "start", pass: false, ...}]`.
